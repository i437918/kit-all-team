**1C Team Kit** — интерактивный установщик рабочего окружения для команд разработки и сопровождения 1С. Он собирает параметры у пользователя, разворачивает проект из утверждённых источников, подключает выбранный набор 1С skills, настраивает AI-приложение и сохраняет состояние для безопасного обновления или продолжения после ошибки.

## Что такое 1C Team Kit

Продукт закрывает следующие потребности:

- создаёт одинаковое воспроизводимое окружение для конкретного проекта и роли;
- загружает файлы окружения из ветки `content-<project>`;
- получает локальную копию конфигурации 1С из ветки `develop` в каталог `db/`;
- подключает ровно один утверждённый набор 1С skills;
- создаёт и настраивает профиль **Hermes**, включая провайдер **CustomLLM** и обязательные MCP `v8std`, `customllm-jira`, `customllm-confluence`; подготовленный контракт `v0.1.5` добавляет к этому профилю OfficeCLI;
- сохраняет встроенные и Learned skills **Hermes**, не заменяя их выбранным внешним набором;
- для других AI-приложений создаёт готовую инструкцию `.teamkit/handoff.txt`;
- сохраняет квитанцию операции, чтобы после устранимого сбоя использовать `retry`, а не начинать всё заново;
- безопасно обновляет ранее созданное окружение без поиска папок по диску или сети.

**Team Kit** не изменяет системное хранилище сертификатов, не публикует секреты, не выполняет `git push` и не записывает изменения непосредственно в ветку `develop`.

> **Важно: развитие проектной ветки**
>
> После первичной установки команда проекта адаптирует документацию и настройки окружения под требования проекта и принятые практики, а затем самостоятельно публикует проверенный комплект обратно в проектную ветку, например [`content-apa`](https://gitlab.example.invalid/1c/aisuz/ai/-/tree/content-apa?ref_type=heads). **Team Kit** не выполняет `git push`: публикацию контролирует команда проекта. Благодаря этому следующие установки и обновления смогут получать из проектной ветки уже актуальный согласованный набор документации и настроек конкретного проекта.

## Что подготовить до установки

Перед запуском убедитесь, что у вас есть:

- Windows 10/11 x64, macOS 15, Ubuntu/Linux x64 либо ALT Linux p11 x64;
- доступ к корпоративной сети или VPN;
- доступ к `gitlab.tools.enterprise.ru`;
- системный Git, доступный из PowerShell или Terminal;
- логин **GitLab** и персональный токен с правом чтения нужных репозиториев. Создайте токен по корпоративной инструкции [«Получение персонального токена в GitLab»](https://docs.example.invalid/spaces/DAT/pages/323493884/Получение+персонального+токен+в+GitLab);
- идентификатор своего проекта: `aisuz`, `apa`, `asbnu`, `asku`, `easr`, `eisko`, `esed`, `uat`, `unip`, `zup` или `wms`;
- роль: аналитик, программист или архитектор;
- выбор одного набора 1С skills:
  - `cc_1c_skills от Широкова`; [Nikolay-Shirokov/cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills)
  - `ai_rules_1c от Филиппова`; [comol/ai_rules_1c](https://github.com/comol/ai_rules_1c)
- отдельный абсолютный путь для окружения, например `C:\TeamKit\apa`;
- свободное место для файлов окружения и локальной копии базы;
- выбранное AI-приложение.

Сравнение доступных наборов:

| Набор | Основной акцент | Что содержит |
| --- | --- | --- |
| `cc_1c_skills от Широкова` | Практическая разработка и проверка решений 1С | `72` каталога skills (`303` файла): метаданные и XML, работа с Конфигуратором, формы, отчёты, расширения и веб-клиент |
| `ai_rules_1c от Филиппова` | Общие правила и согласованные процессы работы AI-агентов с 1С | `11` каталогов skills (`115` файлов), публикуемых **Team Kit** из `content/skills`; в исходном репозитории также находятся `34` rules, `13` описаний субагентов и `13` команд |

Наборы решают разные задачи, поэтому один из них не является безусловно «лучшим». Выберите набор по рабочему процессу команды. **Team Kit** устанавливает ровно один вариант и привязывает его к проверенной версии из каталога продукта.

Если выбран **Hermes**, дополнительно подготовьте:

- ключ **CustomLLM** для модели **`generic-development`**. Это отдельный ключ LLM-провайдера: он отличается от GitLab token, который нужен только для чтения репозиториев. Порядок получения и подключения ключа приведён в корпоративной инструкции [«Подключение к LLM через API (IDE, SDK)»](https://docs.example.invalid/spaces/IDP/pages/1017637995/%D0%9F%D0%BE%D0%B4%D0%BA%D0%BB%D1%8E%D1%87%D0%B5%D0%BD%D0%B8%D0%B5+%D0%BA+LLM+%D1%87%D0%B5%D1%80%D0%B5%D0%B7+API+IDE+SDK);
- обязательный персональный `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` для MCP Jira и обязательный персональный `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` для MCP Confluence. Получите оба токена по корпоративной [инструкции подключения mcp-atlassian](https://docs.example.invalid/spaces/BLOKL/pages/1005956195/Инструкция+по+подключению+MCP-сервера+mcp-atlassian+в+AI-ассистент+Cline). Используйте только собственные токены пользователя; не применяйте общий или чужой токен;
- файл `certs.zip` из раздела `Assets` → `Other` того же **GitLab Release**, если **Windows**, **Git** или **Hermes** не доверяют корпоративной цепочке сертификатов и поэтому не могут установить защищённое HTTPS-соединение с внутренними сервисами. **Team Kit** использует этот архив локально для нужных подключений, но не устанавливает сертификаты в системное хранилище и не меняет системные настройки доверия;
- установленный **Hermes** версии `>= 0.20.1 и < 0.21.0` **или** возможность установить его вручную через файл `Hermes-Setup.exe` в **Windows**. **Hermes** создаёт и запускает изолированный профиль AI-агента, хранит его встроенные и Learned skills, подключает выбранный внешний набор, провайдера **CustomLLM** и MCP. Если совместимый **Hermes** уже доступен, **Team Kit** обнаружит и проверит его автоматически; если его нет, установите **Hermes** через графический установщик, откройте новое окно **PowerShell** и повторите команду **Team Kit**.

Если выбран Cursor, Claude Code, Codex, OpenCode, Kilo Code, Kimi, Qwen, Command Code, Cline или Pi, приложение должно быть установлено заранее, а его команда должна находиться через системный `PATH`.

## Что будет создано

После успешной установки:

- в `KIT_ALL_TEAM_HOME` появятся файлы окружения выбранного проекта;
- в `KIT_ALL_TEAM_HOME\db` появится локальная копия конфигурации из ветки `develop`;
- открытые ответы мастера будут записаны в рабочий `.env` без токенов и LLM-ключей;
- план, квитанция и служебное состояние будут записаны в `.teamkit/`;
- `.gitignore` исключит `.env`, `/db/` и `/.teamkit/` из публикации;
- приватные значения будут сохранены в отдельном owner-only `.env` выбранного AI-приложения;
- для **Hermes** будет создан профиль вида `1c-<project>-<role>-<toolchain>`;
- профиль **Hermes** сохранит встроенные и Learned skills и получит ровно один выбранный внешний набор;
- файл `config.yaml` профиля **Hermes** получит провайдер **CustomLLM**; в `v0.1.5` профиль после настройки содержит четыре MCP: v8std, Jira, Confluence и OfficeCLI;
- для другого AI-приложения появится `.teamkit/handoff.txt` с дальнейшими действиями;
- успешное окружение будет добавлено в локальный MRU-реестр абсолютных путей.

Один каталог `KIT_ALL_TEAM_HOME` соответствует ровно одному проекту и одному окружению.

## Установка в Windows

Текущее меню `Добавить/Обновить` появляется только при интерактивном `teamkit apply`. Команды `apply --non-interactive`, `plan`, `status`, `retry` и `update` сохраняют обратную совместимость, включая параметры и машиночитаемые форматы. `apply --non-interactive` и `plan` не используют обнаружение через локальный реестр; `plan` и `status` не записывают локальный реестр.

### Шаг 1. Скачайте файлы

1. Создайте каталог `C:\TeamKitInstaller`.
2. Скачайте [teamkit-v0.1.3-windows-amd64.exe](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3).
3. Скачайте [SHA256SUMS](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3).
4. Если используете **Hermes**, скачайте файл `certs.zip` из раздела `Assets` → `Other` на странице **GitLab Release** и положите рядом с файлом `teamkit-v0.1.3-windows-amd64.exe`.
5. Если **Hermes** ещё не установлен, скачайте его с [официального сайта](https://hermes-agent.nousresearch.com/) либо используйте файл `Hermes-Setup.exe` из раздела `Assets` → `Other` этого **GitLab Release**.

### Шаг 2. Проверьте **Team Kit**

Откройте **Windows PowerShell**. Командная строка должна начинаться с `PS`. Выполните:

```powershell
New-Item -ItemType Directory -Path 'C:\TeamKitInstaller' -Force | Out-Null
Set-Location -LiteralPath 'C:\TeamKitInstaller'
$file = 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe'
$sum = Get-Content -LiteralPath 'C:\TeamKitInstaller\SHA256SUMS' | Where-Object { $_ -match '^([0-9a-f]{64})  teamkit-v0\.1\.3-windows-amd64\.exe$' } | Select-Object -First 1
if ($sum -notmatch '^([0-9a-f]{64})  ') { throw 'Не найдена строка SHA-256 для Windows-бинарника' }
$expected = $Matches[1]
$actual = (Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA-256 не совпадает: $actual" }
& $file --version
```

Ожидаемый результат версии должен содержать:

- `"version":"v0.1.3"`;

Если SHA-256 или версия не совпали, не запускайте файл. Скачайте его заново из **GitLab Release**.

### Шаг 3. Подготовьте AI-приложение

#### **Hermes** уже установлен

- Не вводите `HERMES_HOME` и не подбирайте каталог вручную.
- **Team Kit** найдёт безопасную установку **Hermes** через стандартные каталоги и `PATH`.
- Поддерживается версия `>= 0.20.1 и < 0.21.0` с доказанной schema 34 или 37.
- Положите файл `certs.zip` рядом с исполняемым файлом **Team Kit**, если архив нужен для корпоративной сети.

#### **Hermes** ещё не установлен

1. Запустите проверенный `Hermes-Setup.exe` двойным щелчком.
2. Завершите графический мастер.
3. Закройте PowerShell и откройте новое окно.
4. Повторно запустите **Team Kit**. Каталог **Hermes** будет найден автоматически.

Для резервного `Hermes-Setup.exe` проверяйте актуальную подпись издателя по организационной процедуре; не переносите контрольные суммы из прежних выпусков.

#### Выбрано другое AI-приложение

Установите приложение заранее, откройте новое окно **PowerShell** и убедитесь, что его команда доступна через `PATH`. **Team Kit** не устанавливает альтернативные AI-приложения. Если приложение отсутствует, возвращается `AI_APP_REQUIRED`; после успешной установки дальнейшие действия сохраняются в файле `.teamkit/handoff.txt`.

### Шаг 4. Запустите мастер

```powershell
& 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe' apply
```

Первым должно появиться меню:

1. `Добавить новое окружение`;
2. `Обновить существующее окружение`.

До выбора **Team Kit** ничего не создаёт и не изменяет.

### Ветка A. Новое окружение

Выберите `1`, если **Team Kit** ещё не настраивал этот проект.

Мастер последовательно запросит:

1. операционную систему — `Windows`;
2. AI-приложение;
3. только для приложения не **Hermes** — установлено ли оно;
4. абсолютный путь `KIT_ALL_TEAM_HOME`, например `C:\TeamKit\apa`;
5. проект;
6. роль;
7. один набор skills.

В последнем вопросе выберите `cc_1c_skills от Широкова` либо `ai_rules_1c от Филиппова`. Одновременно установить оба набора нельзя.

Для **Hermes** вопросы `AI-приложение уже установлено?` и `Введите HERMES_HOME` не задаются. Если один из них появился после выбора **Hermes**, остановитесь и проверьте версию **Team Kit** командой `--version`.

Когда понадобятся доступы, **Team Kit** отдельно запросит без отображения символов:

- `Логин GitLab (GITLAB_USERNAME)`;
- `Токен GitLab (GITLAB_TOKEN)`;
- `Ключ CustomLLM (HERMES_CUSTOM_LLM_API_KEY)` — только для **Hermes**.

Не передавайте эти значения как параметры команды и не сохраняйте их в README, тикете или снимке экрана.

### Ветка B. Обновление окружения

Выберите `2`, если окружение ранее успешно создавалось **Team Kit**.

Путь определяется в следующем порядке:

1. явный `--kit-home` имеет наивысший приоритет;
2. локальный MRU-реестр окружений;
3. `KIT_ALL_TEAM_HOME` из переменной среды;
4. ручной ввод абсолютного пути.

При этом ошибка явного `--kit-home` завершает команду без перехода к другим источникам. **Team Kit** не сканирует диски или сеть.

После проверки сводки выберите:

1. `Ничего` — безопасный выход без сети и записи;
2. `Только файлы окружения`;
3. `Только файлы базы данных`;
4. `Файлы окружения и базы данных`.

Если появилось `RETRY_REQUIRED`, обновление не началось. Перейдите к ветке C.

### Ветка C. Восстановление незавершённой установки

Используйте эту ветку после устранимой ошибки или для окружения со статусом `needs_apply`.

1. Устраните причину ошибки: сеть, сертификат, токен, установленное приложение или безопасные права файла.
2. Не удаляйте каталоги `.teamkit/`, файлы `.env`, профиль **Hermes** или уже созданные каталоги.
3. Выполните готовую команду `retry`, которую напечатал **Team Kit**, либо укажите точный путь:

```powershell
& 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe' retry --kit-home 'C:\TeamKit\apa'
```

`v0.1.3` умеет продолжать операции, остановленные на настройке профиля. Для доказанного staging-файла `.env`, принадлежащего **Team Kit**, программа безопасно устанавливает owner-only права без изменения содержимого. Для точного профиля, созданного прежней установкой **Team Kit** без bundled skills, выполняется официальный `hermes -p <identity> skills opt-in --sync`. Общий `hermes update` не запускается.

Изменённый пользователем marker считается осознанным opt-out и возвращает `HERMES_BUNDLED_SKILLS_USER_OPT_OUT` без изменения профиля.

### Always-on Jira и Confluence для Hermes

Для профиля **Hermes** Team Kit автоматически включает MCP Jira и Confluence. `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` и `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` обязательны и должны быть персональными токенами текущего пользователя. Мастер запрашивает `HERMES_CUSTOM_LLM_API_KEY`, `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` (`Jira personal token`) и `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` (`Confluence personal token`) маскированно. Значения хранятся только в protected owner-only profile `.env`; не передавайте их через аргументы или URL. Порядок получения токенов приведён в корпоративной [инструкции подключения mcp-atlassian](https://docs.example.invalid/spaces/BLOKL/pages/1005956195/Инструкция+по+подключению+MCP-сервера+mcp-atlassian+в+AI-ассистент+Cline). При устранимой ошибке используйте `retry`: он продолжает незавершённую операцию без нового `apply`.

## Как устанавливаются skills **Hermes**

Новый профиль **Hermes** создаётся без флага `--no-skills`. Поэтому после успешной установки в профиле одновременно остаются:

- встроенные skills **Hermes**;
- Learned и пользовательские skills, которыми управляет сам **Hermes**;
- ровно один внешний набор **Team Kit**: `cc_1c_skills` **или** `ai_rules_1c`.

**Team Kit** проверяет конфликт имён до миграции и не перезаписывает одноимённый bundled skill. Публикация внешнего набора возобновляема: после сбоя `retry` продолжает незавершённые шаги и повторно проверяет уже опубликованные файлы.

## MCP v8std

Для профиля **Hermes** **Team Kit** настраивает удалённый MCP-сервер `v8std` по адресу `https://ai.v8std.ru/mcp`. Он даёт AI-агенту доступ на чтение к базе стандартов и диагностик 1С: позволяет искать стандарт по номеру или фразе, получать полный текст требования, находить связанные рекомендации и пояснять диагностики BSL, EDT и АПК. MCP не изменяет код проекта и не запускает проверки самостоятельно.

- описание сервера и доступных инструментов: [v8std MCP](https://v8std.ru/mcp/);
- исходный код: [zeegin/v8std](https://github.com/zeegin/v8std).

Это внешний публичный сервис: текст поискового запроса передаётся серверу, поэтому не отправляйте закрытый код, коммерческие данные, токены, пароли и другие секреты. Для поиска формулируйте обезличенный вопрос, номер стандарта или текст диагностики.

## MCP Jira

Включённый сервер `customllm-jira` подключает Hermes к корпоративной Jira: AI-агент может искать и читать доступные пользователю проекты и задачи, получать их поля и комментарии и выполнять поддерживаемые сервером операции в пределах прав персонального токена. Сервер использует `https://llm.example.invalid/jira/mcp`, базовый заголовок `x-litellm-api-key: Bearer ${HERMES_CUSTOM_LLM_API_KEY}` и персональный заголовок `x-mcp-jira-authorization: Token ${HERMES_CUSTOM_ISSUE_TRACKER_TOKEN}`.

`HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` обязателен, принадлежит текущему пользователю и определяет доступные проекты и задачи. Team Kit хранит значение только в owner-only `.env` профиля Hermes; в `config.yaml` остаётся ссылка `${HERMES_CUSTOM_ISSUE_TRACKER_TOKEN}`, а не значение секрета.

## MCP Confluence

Включённый сервер `customllm-confluence` подключает Hermes к корпоративной Confluence: AI-агент может искать и читать доступные пользователю пространства и страницы и выполнять поддерживаемые сервером операции в пределах прав персонального токена. Сервер использует `https://llm.example.invalid/confluence/mcp`, базовый заголовок `x-litellm-api-key: Bearer ${HERMES_CUSTOM_LLM_API_KEY}` и персональный заголовок `x-mcp-confluence-authorization: Token ${HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN}`.

`HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` обязателен, принадлежит текущему пользователю и определяет доступные пространства и страницы. Team Kit хранит значение только в owner-only `.env` профиля Hermes; в `config.yaml` остаётся ссылка `${HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN}`, а не значение секрета.

## MCP OfficeCLI в v0.1.5

Этот раздел описывает подготовленный, но не опубликованный контракт `v0.1.5`. OfficeCLI добавляется только в профиль Hermes; для других приложений Team Kit его не настраивает. Закреплена exact версия `v1.0.144` и SHA-256 каждого платформенного файла. Выбрана именно эта версия, потому что только её исходники и четыре asset были сопоставлены с immutable evidence; `latest` не принимается автоматически. Исходная запись нейтральна к результату. Итог runtime определяется только на основании external exact-SHA evidence, привязанного к SHA кандидата; успешный инженерный результат сам по себе не публикует `v0.1.5` и не закрывает отдельные corporate Windows/release gates.

Исполняемый файл находится по управляемому пути `${HERMES_HOME}/.teamkit/officecli/v1.0.144/officecli` (`officecli.exe` в Windows). Team Kit не изменяет PATH, не запускает произвольный installer/updater, не удаляет старые pinned versions и не переносит OfficeCLI в системный каталог. Перед MCP-запуском выполняются `officecli config autoUpdate false`, обязательный `officecli config autoUpdate` read-back и независимая проверка user-global файла `${UserProfile}/.officecli/config.json`. `OFFICECLI_SKIP_UPDATE` не используется как MCP control: upstream обрабатывает команду `mcp` раньше этого guard.

При `autoUpdate=false` допускается best-effort refresh только ранее установленных OfficeCLI skills во всех обнаруженных agent homes. Skills — файловые instruction/reference packs, например `officecli-pptx`, `officecli-docx`, `officecli-xlsx` и другие, а не дополнительные MCP-серверы; refresh может перезаписать локальные изменения внутри уже существующего skill. Team Kit не устанавливает on-disk skills, не полагается на default Hermes skill directory и использует встроенную команду `load_skill` единственного MCP-инструмента `officecli`.

Если обнаружены updater-соседи, установка останавливается fail-closed. Только после подтверждённого `autoUpdate=false` cleanup ограничен файлами `.update`, `.update.partial`, `.old` внутри принадлежащего Team Kit managed parent. `retry` повторно использует существующий `configure_application`; он не начинает новый installer flow.

Инструмент `officecli` может читать и изменять документы Office, включая Word, Excel и PowerPoint. Это намеренно широкая граница мутаций: передавайте только рабочие файлы, для которых пользователь разрешил чтение и запись, и храните резервную копию. Поддерживаемые assets и точные SHA pins приведены в [qualification record](docs/OFFICECLI-QUALIFICATION.md). Публикация `v0.1.5` без external exact-SHA evidence для четырёх native lanes и отдельного ALT p11 smoke запрещена.

## Проверка результата

Проверьте состояние:

```powershell
& 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe' status --kit-home 'C:\TeamKit\apa'
```

Ожидаемый итог — `ready`.

Для **Hermes**:

1. полностью закройте и снова откройте **Hermes**;
2. выберите профиль, имя которого показал **Team Kit**, например `1c-apa-developer-cc_1c_skills`;
3. в разделе `Skills` проверьте наличие встроенных skills **Hermes** и выбранного внешнего набора;
4. для опубликованного `v0.1.3` проверьте три включённых сервера: `v8std`, `customllm-jira`, `customllm-confluence`; после квалифицированного `v0.1.5` ожидаются четыре MCP, включая OfficeCLI;
5. если профиль не появился, сначала снова выполните `status`, а не создавайте MCP или файл `config.yaml` вручную.

Для другого AI-приложения откройте файл `.teamkit/handoff.txt` и выполните указанную там инструкцию в выбранном приложении.

## Устранение ошибок

| Ошибка | Что означает | Что делать |
|---|---|---|
| `AI_APP_REQUIRED` | Альтернативное AI-приложение не найдено. | Установить приложение, открыть новое окно PowerShell и повторить `apply`. |
| `HERMES_HOME_AUTO_DETECT_FAILED` | Безопасный каталог **Hermes** не найден однозначно. | Завершить установку **Hermes**, открыть новое окно **PowerShell** и повторить. Не подбирать путь случайно. |
| `HERMES_VERSION_UNSUPPORTED` | Версия вне диапазона `>= 0.20.1 и < 0.21.0`. | Установить совместимую версию **Hermes**. |
| `HERMES_EXECUTABLE_UNVERIFIED` | Не удалось безопасно подтвердить первый `hermes` в `PATH`. | Проверить установку и открыть новый PowerShell. `--hermes-home` допустим только для автоматизации, администрирования или исключительной ситуации и не отключает проверки. |
| `HERMES_CONFIG_SCHEMA_UNSUPPORTED` | Runtime не доказал schema 34 или 37. | Не изменять файл `config.yaml` вручную; установить поддерживаемый **Hermes**. |
| `CERTIFICATE_ARCHIVE_REQUIRED` | Не найден проверенный файл `certs.zip`. | Скачать его из раздела `Assets` → `Other` текущего **GitLab Release** и положить рядом с **Team Kit**. |
| `SECRET_FILE_PERMISSIONS_UNSAFE` | Приватный файл имеет небезопасные права. | Для операции **Team Kit** выполнить `retry`; если ошибка повторяется, остановиться и передать путь администратору. Не удалять файл и не расширять DACL вручную. |
| `RETRY_REQUIRED` | Существует незавершённая операция. | Выполнить целиком напечатанную команду `retry`. |
| `LOCAL_CHANGES_DETECTED` | В Git-дереве есть локальные изменения. | Сохранить изменения самостоятельно и повторить обновление. **Team Kit** не делает `reset` или `stash`. |
| `FOREIGN_WORKSPACE` | Папка не является ожидаемым окружением **Team Kit**. | Выбрать отдельную пустую папку либо правильное существующее окружение. |

При ошибке сети или TLS проверьте VPN, доступ к **GitLab**, срок действия токена и файл `certs.zip`. После исправления используйте `retry`, а не повторный `apply` в той же папке.

## macOS

Поддерживаются **macOS 15** на Intel и Apple Silicon. Перед началом подготовьте VPN, доступ к **GitLab**, системный **Git**, ключ **CustomLLM** для **Hermes** и отдельный каталог окружения, например `$HOME/TeamKit/apa`.

### Шаг 1. Определите архитектуру

Откройте `Terminal` и выполните:

```bash
uname -m
```

- результат `x86_64` — скачивайте `teamkit-v0.1.3-darwin-amd64`;
- результат `arm64` — скачивайте `teamkit-v0.1.3-darwin-arm64`;
- при другом результате остановитесь: подходящего бинарника в выпуске нет.

### Шаг 2. Скачайте и проверьте файлы

1. Создайте каталог `$HOME/TeamKitInstaller`.
2. Из **GitLab Release v0.1.3** скачайте в этот каталог [бинарник для Intel](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3) либо [бинарник для Apple Silicon](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3), а также файл [SHA256SUMS](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3).
3. Перейдите в каталог и выберите имя бинарника:

```bash
cd "$HOME/TeamKitInstaller"
binary='teamkit-v0.1.3-darwin-arm64' # для Intel укажите teamkit-v0.1.3-darwin-amd64
expected="$(awk -v file="$binary" '$2 == file {print $1}' SHA256SUMS)"
actual="$(shasum -a 256 "$binary" | awk '{print $1}')"
test -n "$expected" && test "$actual" = "$expected" || { echo 'SHA-256 не совпадает'; exit 1; }
chmod 700 "$binary"
"./$binary" --version
```

Версия должна быть `v0.1.3`. Бинарник не подписан Apple и не notarized; разрешайте его запуск только способом, одобренным вашей организацией. При несовпадении SHA-256 или версии удалите файл и скачайте его заново.

### Шаг 3. Запустите мастер

```bash
cd "$HOME/TeamKitInstaller"
binary='teamkit-v0.1.3-darwin-arm64' # для Intel укажите teamkit-v0.1.3-darwin-amd64
"./$binary" apply
```

В первом меню выберите `Добавить новое окружение` либо `Обновить существующее окружение`. При добавлении выберите `macOS`, затем AI-приложение, проект, роль и один набор skills. Для `KIT_ALL_TEAM_HOME` можно использовать `$HOME/TeamKit/apa`. **Hermes** устанавливается и проверяется **Team Kit** автоматически; вопросы `AI-приложение уже установлено?` и `Введите HERMES_HOME` для него не появляются.

### Шаг 4. Проверьте результат

```bash
cd "$HOME/TeamKitInstaller"
binary='teamkit-v0.1.3-darwin-arm64' # для Intel укажите teamkit-v0.1.3-darwin-amd64
"./$binary" status --kit-home "$HOME/TeamKit/apa"
```

Ожидаемый статус — `ready`. Для **Hermes** дополнительно откройте созданный профиль и проверьте встроенные skills, выбранный внешний набор и MCP `v8std`. Если установка остановилась на устранимой ошибке, исправьте причину и выполните напечатанную команду `retry`, не удаляя `.env` и `.teamkit/`.

```bash
uname -m
```

## Безопасность и ограничения

- Выпуск внутренний и неподписанный.
- macOS-бинарники не подписаны Apple и не notarized.
- Установка **Hermes** в **Windows** выполняется вручную через GUI.
- Не передавайте токены и ключи через параметры, URL, сообщения или снимки экрана.
- Не публикуйте `.env`, `.teamkit/`, `db/`, `certs.zip` и каталоги профилей.
- Не размещайте `HERMES_HOME` внутри `KIT_ALL_TEAM_HOME` и наоборот.
- Не запускайте **Team Kit** от имени другого пользователя между `apply` и `retry`.
- Не создавайте файл `config.yaml`, MCP и lock-файлы skills вручную.
- Trusted corporate network probe не является release-gate: GitHub-hosted runner не разрешает внутренний DNS.
- ALT Linux не подтверждена на нативном runner или в QEMU/VM.
- В подготовленном `v0.1.5` OfficeCLI может читать и изменять документы Office; внешний exact-SHA verdict не меняет эту широкую mutation boundary.

## Команды обслуживания

```text
teamkit plan --non-interactive ...
teamkit apply
teamkit status --kit-home <абсолютный путь>
teamkit retry --kit-home <абсолютный путь>
teamkit update --kit-home <абсолютный путь> --target content|database|both
teamkit version
```

Интерактивное меню `Добавить/Обновить` появляется только у `apply`. Команды `plan` и `status` не записывают локальный реестр. `apply --non-interactive` и `plan` не используют обнаружение окружений через MRU-реестр.
