# План выпуска v0.1.0-rc.2

## Этап 1. Подготовить release commit

- [ ] Заменить `rc.1` на `rc.2` только в активных build/CI/workflow defaults,
      release checklist, CHANGELOG и точных release-contract tests.
- [ ] Не менять исторические `docs/superpowers/**` и опубликованные данные `rc.1`.
- [ ] Выполнить `go vet ./...`, `go test ./... -count=1`, workflow/actionlint и
      проверки скриптов.
- [ ] Провести отдельное ревью и fast-forward опубликовать release commit в master.

## Этап 2. Получить и проверить точные кандидаты

- [ ] Дождаться успешного GitLab pipeline release commit.
- [ ] По возможности создать приватное GitHub-зеркало и получить native
      Windows/Linux/macOS и ALT userspace evidence для тех же исходников.
- [ ] Скачать точные CI artifacts; проверить имена, встроенные version/commit,
      SHA256SUMS и SECURITY-AUDIT.json.
- [ ] Зафиксировать честные внешние ограничения native macOS/ALT QEMU/network.
- [ ] Провести отдельное ревью evidence.

## Этап 3. Создать GitLab tag и Release

- [ ] Повторно проверить отсутствие `v0.1.0-rc.2` tag/release.
- [ ] Создать аннотированный тег на exact release commit без force.
- [ ] Загрузить восемь постоянных assets: четыре бинарника, SHA256SUMS,
      SECURITY-AUDIT.json, certs.zip и Hermes-Setup.exe.
- [ ] Создать internal unsigned GitLab prerelease с честными ограничениями.
- [ ] Повторно скачать каждый asset и проверить SHA-256; проверить EXE signer.
- [ ] Провести отдельное ревью удалённого релиза.

## Этап 4. Обновить пользовательскую документацию

- [ ] Обновить README и INSTALL фактическими ссылками, commit и хешами rc.2.
- [ ] Обновить EXTERNAL-BLOCKERS и checklist фактическими результатами.
- [ ] Выполнить полный test/vet/diff/security scan и отдельное ревью.
- [ ] Fast-forward опубликовать docs-only commit в master и подтвердить SHA.
