# v0.1.0 Final Internal Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the exact tested `v0.1.0` final internal release in GitLab while documenting accepted network and ALT limitations and preserving immutable RC1/RC2 history.

**Architecture:** A prospective release commit changes active build, CI, documentation, and validation contracts from `v0.1.0-rc.2` to `v0.1.0`. The identical commit is fast-forwarded to GitHub `main` and GitLab `master`, independently built and tested, and the byte sets are compared. GitHub remains a read-only validation/evidence mirror and must not create a tag or Release. GitLab is the only publisher: six kept job artifacts are listed in Release notes, while the existing verified `Hermes-Setup.exe` and `certs.zip` project uploads are the only `Other` links.

**Tech Stack:** Go 1.26.6, GitHub Actions, GitLab CI/API, PowerShell 7, Bash, Git, SHA-256, Authenticode.

## Global Constraints

- Version and tag are exactly `v0.1.0`; classification is final/non-prerelease, private/internal, unsigned.
- Trusted corporate-network evidence is not a release gate and must be disclosed as unavailable for the exact release commit.
- ALT p11 userspace is required; native ALT and QEMU/VM evidence are not release gates and must be disclosed as unverified.
- Windows Hermes installation remains a manual GUI operation; the signed fallback installer does not prove unattended installation.
- GitHub `main` and GitLab `master` must point to the identical prospective release commit before final evidence is accepted.
- RC1/RC2 tags, releases, commands, hashes, dated plans, and `legacyRC2OperationContract` are immutable and must not be rewritten.
- No artifact is rebuilt after its exact job has been selected for publication.
- GitLab CI must skip tag pipelines; pushing `v0.1.0` must not rebuild `dist/`.
- The rollback boundary is creation of the annotated protected `v0.1.0` tag. After tag creation, finish forward; never move or delete it without separate explicit authorization.
- GitLab Release presentation must contain exactly two `Other` links (`Hermes-Setup.exe`, `certs.zip`); the four binaries, `SHA256SUMS`, and `SECURITY-AUDIT.json` are individual Markdown bullets in notes that reference the kept master job.
