# v0.1.3 Corporate Atlassian MCP Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить `v0.1.3` от тега `v0.1.2` с обязательными корпоративными Jira и Confluence MCP для Hermes, не потеряв возможности актуальной релизной линии.

**Architecture:** Новая ветка создаётся непосредственно от `v0.1.2`; старые feature-коммиты не cherry-pick-ятся. MCP-декларации остаются закрытым каталогом, профиль хранит только `${ENV}`-ссылки, credentials сохраняет значения через существующие private stores, а operation contract связывает точные публичные параметры без значений секретов.

**Tech Stack:** Go 1.26.6, `gopkg.in/yaml.v3`, PowerShell/Windows ACL, GitHub Actions, GitLab CI, Hermes Agent 0.20.x.

## Global Constraints

- База новой ветки: точный тег `v0.1.2`, commit `03b823588dd27e3bd0c0236f417eabbc2aef6ac4`.
- Итоговая версия и имена артефактов: `v0.1.3` и `teamkit-v0.1.3-<platform>`.
- Jira и Confluence всегда включены для Hermes; вопрос выбора не добавляется.
- Обязательные секреты: `HERMES_CUSTOM_LLM_API_KEY`, `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN`, `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN`.
- Точные URL: `https://llm.example.invalid/jira/mcp` и `https://llm.example.invalid/confluence/mcp`.
- Точные заголовки: `x-litellm-api-key`, `x-mcp-jira-authorization`, `x-mcp-confluence-authorization`.
- Секреты не передаются в argv и не появляются в Git, YAML как литералы, operation contract, plan, receipt, stdout, stderr или execution log.
- Существующие runtime discovery, migration, recovery, registry и environment flows `v0.1.2` сохраняются.
- Каждый production-шаг выполняется RED → GREEN и заканчивается отдельным Conventional Commit.
