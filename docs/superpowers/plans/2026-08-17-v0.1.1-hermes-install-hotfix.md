# v0.1.1 Hermes Installation Hotfix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Выпустить узкий `v0.1.1`, который совместим с реальными Hermes 0.20.x, сохраняет bundled skills, безопасно мигрирует только доказанные профили Team Kit и не изменяет выпуски `v0.1.0`/RC2.

**Architecture:** Сначала один bounded runtime probe связывает executable, Install directory, schema 34/37 и bundled inventory. Затем узкие profile/toolchain primitives выполняют только доказанные мутации, а bootstrap вызывает их как идемпотентные предусловия Action 50/90. Release строится один раз для exact SHA, независимо проверяется в GitLab и GitHub, после чего сравниваются все шесть публикуемых файлов.

**Tech Stack:** Go 1.26.6, стандартная библиотека Go, `golang.org/x/sys/windows`, YAML v3, PowerShell, Bash, GitLab CI, GitHub Actions.

## Global Constraints

- Основание плана — exact spec commit `fa486babda0c04f6423afcc4136c91e6639e5331` и `docs/superpowers/specs/2026-08-17-v0.1.1-hermes-install-hotfix-design.md`.
- Поддерживаемый Hermes: `>= 0.20.1` и `< 0.21.0`; версия не определяет schema.
- Разрешены только доказанные `_config_version` 34 и 37; managed commit `f80f453ae0679347e38abc917c7f94f717bf96c5` остаётся без repin.
- Team Kit сохраняет штатные bundled skills и устанавливает ровно один выбранный внешний toolchain.
- Не следовать symlink/junction/reparse point; все читаемые файлы и обходы имеют малые явные пределы.
- Не выводить токены, `.env`, произвольный вывод Hermes или секретные значения `config.yaml`.
- Не копировать Learned skills, не удалять sessions/user data и не выполнять общий `hermes update`.
- Защищённый тег и записанные SHA/хеши определяют `v0.1.0`; этот hotfix не меняет его Release/job artifacts, evidence или исторические RC2-разделы.
- Каждая Task выполняется свежим executor-агентом. После GREEN отдельный свежий spec-reviewer сверяет только требования Task со spec, затем другой свежий code-quality reviewer проверяет безопасность, тесты и diff. Executor исправляет замечания и повторяет оба review gate до `APPROVED`.
- Каждая Task строго проходит RED → GREEN → focused gate → full gate → отдельный conventional commit. Следующая Task не начинается до чистого worktree и двух approvals.
- До Task 8 запрещены push, tag, Release и иные внешние публикации.

- [ ] **Step 4: Implement the bounded same-root contract**

Implement `VerifyRuntimeContract` in this order: validate every existing parent component of executable/Install directory; `VerifyExecutable`; exact help probes; acquire one `openedInstallRoot` handle/fd; read only `hermes_cli/config_defaults.py` through that handle; inventory only `skills` through that same handle; hash canonical sorted names/paths; verify root handle and executable identity again; close once; return sorted values. The private schema/inventory readers accept only `openedInstallRoot` and have no path-based fallback. `Discover` stores this exact contract in `DiscoveryResult.Contract` and must not re-run a looser executable-only probe.

```go
func VerifyRuntimeContract(ctx context.Context, executable string, capture executableCapture) (RuntimeContract, error) {
	info, err := VerifyExecutable(ctx, executable, capture)
	if err != nil { return RuntimeContract{}, err }
	if err := verifyCapability(ctx, info.Executable, capture, []string{"profile", "create", "--help"}, "--no-alias"); err != nil { return RuntimeContract{}, err }
	if err := verifyCapability(ctx, info.Executable, capture, []string{"skills", "opt-in", "--help"}, "--sync"); err != nil { return RuntimeContract{}, err }
	root, err := openVerifiedInstallRoot(info)
	if err != nil { return RuntimeContract{}, err }
	defer root.Close()
	schema, err := probeConfigSchema(root)
	if err != nil { return RuntimeContract{}, err }
	skills, err := inventoryBundledSkills(root)
	if err != nil { return RuntimeContract{}, err }
	identity := root.Identity()
	if err := root.VerifyIdentity(identity); err != nil { return RuntimeContract{}, err }
	digest := bundledInventorySHA256(skills)
	return RuntimeContract{Info: info, Identity: identity, ConfigSchema: schema, BundledSkills: skills, BundledInventorySHA256: digest}, nil
}
```

The platform files must open the install directory without following reparse/symlink components and expose reads relative to that already-open root. Windows uses `CreateFile` with `FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS`; POSIX uses directory fd plus `openat`/`fstatat` with `O_NOFOLLOW`/`AT_SYMLINK_NOFOLLOW`. Reject identity changes before returning.
