# Дизайн пользовательского README

## Цель и аудитория

`README.md` должен стать основной русскоязычной инструкцией для сотрудника, который не обязан разбираться в Git, Go или командной строке. Документ объясняет назначение 1C Team Kit, помогает выбрать и запустить готовый бинарный файл, пройти интерактивный мастер и понять результат. Инструкции разработчика остаются в `AGENTS.md` и не перегружают пользовательский сценарий.

## Структура документа

Материал строится по принципу постепенного раскрытия:

1. Краткое объяснение продукта и результата установки.
2. Честная таблица поддержки Windows, macOS, Linux и ALT Linux.
3. Подготовка: доступ к GitLab, установленное AI-приложение и отдельная папка одного проекта.
4. Загрузка актуального RC из GitLab и необязательная проверка SHA-256.
5. Отдельные команды запуска для каждой ОС.
6. Основной интерактивный сценарий: запуск без длинного набора параметров и ответы на вопросы мастера.
7. Пояснение вариантов Hermes и других AI-приложений.
8. Описание созданного окружения, обновления, восстановления и проверки состояния.
9. Безопасность, частые ошибки и известные ограничения.
10. Параметры командной строки для опытных пользователей.

## Пользовательский сценарий

Главный путь начинается с `teamkit apply`. README последовательно объясняет вопросы об операционной системе, AI-приложении, наличии приложения, рабочей папке, проекте, роли и единственном наборе правил. Для одного `KIT_ALL_TEAM_HOME` разрешается ровно один проект и одно окружение. В документе перечисляются 11 проектов и три роли, но внутренние термины используются только там, где пользователь увидит их в мастере.

Для Hermes описываются профиль роли, один набор skills, MCP v8std и провайдер CustomLLM. На Windows автоматическая установка отсутствующего Hermes не обещается: пользователь устанавливает его графически и повторяет запуск. Для другого AI-приложения README объясняет выдаваемую строку передачи настройки в чат.

## Достоверность и ограничения

README ссылается на опубликованный GitLab RC `v0.1.0-rc.1`, его четыре бинарных файла, `SHA256SUMS` и отчёт аудита. Windows и Linux описываются как проверенные в доступном контуре. Для macOS честно указываются кросс-сборка без нативной проверки, отсутствие подтверждения Gatekeeper и notarization. Для ALT Linux указывается наличие Linux-бинарника и предусмотренная совместимость без завершённой нативной проверки. Office-документы явно исключены из продукта.

Секреты не предлагается вводить в параметры командной строки. Документ различает публичный `.env` окружения и приватный `.env` AI-приложения, предупреждает не публиковать токены, сертификаты, `db/` и `.teamkit/`. Конфигурация базы описывается как локальная read-only копия ветки `develop`; работа напрямую в `develop` не предлагается.

## Проверка результата

После обновления проверяются:

- русский язык и понятность без специальных знаний;
- соответствие команд фактическому CLI;
- актуальность ссылок, тега, хешей и платформенных оговорок;
- отсутствие секретов и обещаний неподтверждённой поддержки;
- корректность относительных Markdown-ссылок;
- `git diff --check` и тесты документационных контрактов в `test/release`.
