# Дизайн автоматического обнаружения Hermes

## Цель и границы

Team Kit должен сам определить, установлен ли Hermes, найти его рабочий каталог и проверить совместимость. В интерактивном сценарии после выбора Hermes больше не задаются вопросы «AI-приложение уже установлено?», `HERMES_HOME` и версия Hermes. Для остальных AI-приложений вопрос об установке сохраняется.

Флаги `--hermes-home` и `--app-installed` остаются явными переопределениями для автоматизации. Они не ослабляют проверки: `--app-installed=true` требует обнаружить совместимый Hermes, а `--app-installed=false` принудительно выбирает сценарий установки и только определяет безопасный целевой `HERMES_HOME`.

## Поток мастера

Мастер спрашивает операционную систему и AI-приложение. После выбора Hermes он получает `KIT_ALL_TEAM_HOME`, выполняет обнаружение и первично проверяет отсутствие вложения или пересечения `KIT_ALL_TEAM_HOME` и найденного `HERMES_HOME`. Затем мастер продолжает вопросами проекта, роли и toolchain; сервис повторяет эту защитную проверку перед работой.

При найденной установке обычный текстовый режим выводит только:

```text
Hermes найден.
Версия: 0.20.2
HERMES_HOME: G:\.hermes
```

В режиме `--json` этот текст не смешивается с JSON: те же поля передаются в объекте результата. Если Hermes не найден, `AppInstalled=false` назначается автоматически. На Windows последующая установка остаётся ручной и завершается существующей fail-closed ошибкой до выполнения неподтверждённых действий. На macOS, Linux и ALT Linux сохраняется управляемая установка закреплённого исходного кода.

## Приоритет и безопасность обнаружения

Рабочий каталог выбирается строго в следующем порядке:

1. абсолютный путь из `--hermes-home`;
2. безопасное значение переменной среды `HERMES_HOME`;
3. платформенный каталог по умолчанию: `%LOCALAPPDATA%\hermes` в Windows и `$HOME/.hermes` в macOS, Linux и ALT Linux;
4. родитель каталога установки, только если `hermes --version` доказывает одну из явно поддерживаемых стандартных схем размещения и более сильного источника пути нет.

Каждый непустой более сильный источник проверяется до перехода к следующему. Относительный путь, символическая ссылка/reparse point, небезопасный компонент или неоднозначное размещение дают `HERMES_HOME_AUTO_DETECT_FAILED`; программа не подбирает другой случайный каталог. Каталог существующей установки обязан существовать. Для новой установки целевой каталог может отсутствовать, но его существующий ближайший родитель должен пройти проверку безопасности.

Сначала проверяется точный исполняемый файл в выбранном home:

- Windows: `<home>\hermes-agent\venv\Scripts\hermes.exe`;
- POSIX official: `<home>/hermes-agent/venv/bin/hermes`;
- POSIX managed Team Kit: `<home>/.teamkit/hermes-agent-source/venv/bin/hermes`.

Если точного файла нет, проверяется только первый кандидат `hermes` из `PATH`. Полный диск не сканируется. Небезопасный, повреждённый или несовместимый первый кандидат считается затенением и завершает обнаружение ошибкой; Team Kit не ищет следующий executable. Поле `Install directory` из вывода версии подтверждает принадлежность executable каталогу установки, но само по себе не становится `HERMES_HOME`: например, системный `/opt` или FHS-каталог не является пользовательским home.

## Диапазон версии и capability probes

Поддерживается стабильный диапазон `>= 0.20.1` и `< 0.21.0`. Парсер принимает только ограниченный корректный UTF-8 вывод `Hermes Agent vMAJOR.MINOR.PATCH`, извлекает стабильную семантическую версию без shell-интерпретации и сохраняет фактическое значение.

- `0.20.0` и ниже, а также `0.21.0` и выше возвращают `HERMES_VERSION_UNSUPPORTED`.
- Точный `0.20.1` использует уже подтверждённый контракт.
- Любая более новая `0.20.x` дополнительно проходит только read-only проверки: `profile --help` должен объявлять `create`, `profile create --help` — флаги `--no-alias` и `--no-skills`, а `doctor --help` — поддерживаемую команду doctor. Команды ограничены по времени и объёму вывода и не создают профиль.
- Ошибка или отсутствие требуемой возможности дают `HERMES_EXECUTABLE_UNVERIFIED`, а не молчаливое принятие версии.

Prerelease, изменённый формат, лишние управляющие байты, невалидный UTF-8 и несогласованный `Install directory` отклоняются как непроверенный executable.

## Архитектура и данные

`internal/hermes` получает три изолированных компонента: строгий парсер версии, read-only проверку возможностей и resolver home/executable. Все внешние операции передаются через узкие зависимости (`LookPath`, чтение среды, файловые проверки и bounded command capture), поэтому матрица тестируется без реального Hermes.

CLI выполняет первичное обнаружение для удобства мастера. Сервис перед `Plan`, `Apply` и повторным выполнением независимо перепроверяет executable, диапазон версии, capabilities и соответствие выбранному home. Между двумя проверками подмена файла или `PATH` приводит к отказу.

В `domain.DesiredState` сохраняются фактический проверенный `HERMES_HOME` и, для уже установленного Hermes, `HermesVersion`. Новые `.env` записывают `HERMES_VERSION`; для управляемой ещё не выполненной установки значение отсутствует. Старые `.env` и квитанции без этого необязательного поля продолжают читаться, но сервис всё равно повторно проверяет runtime. Новые квитанции включают фактическую версию в снимок desired state, а operation contract фиксирует границы `0.20.1` и `0.21.0` и наблюдаемую версию. Секреты и executable path в публичную `.env` не записываются.

## Ошибки и неоднозначности

- `HERMES_HOME_AUTO_DETECT_FAILED` — home отсутствует, небезопасен, неоднозначен или не может быть доказан; сообщение предлагает передать абсолютный `--hermes-home`.
- `HERMES_VERSION_UNSUPPORTED` — корректно распознанная стабильная версия вне диапазона.
- `HERMES_EXECUTABLE_UNVERIFIED` — executable, вывод версии или capability contract не подтверждены.
- `HOME_PATH_OVERLAP` — выбранные `KIT_ALL_TEAM_HOME` и `HERMES_HOME` пересекаются.
- При `--app-installed=true` отсутствие executable является ошибкой, а не переходом к установке.
- При `--app-installed=false` существующий Hermes намеренно не используется; Windows останавливается на ручной установке, POSIX применяет закреплённый managed installer.

## Документация и проверка

README и `docs/INSTALL.md` описывают одну развилку: Hermes найден автоматически либо требуется установка. Они больше не требуют от обычного пользователя вводить `HERMES_HOME`, подтверждать установку или вручную сверять точную версию `0.20.1`; документируется диапазон `0.20.x` начиная с `0.20.1` и назначение override-флагов.

TDD-матрица покрывает оба состояния установки, все источники home, безопасные и небезопасные пути, PATH shadowing, `0.20.0/0.20.1/0.20.2/0.20.99/0.21.0`, capability probes, Windows/macOS/Linux/ALT defaults, legacy `.env`/receipt и интерактивный сценарий без трёх удалённых вопросов. Перед выпуском выполняются полный `go test -mod=vendor -count=1 ./...`, `go vet -mod=vendor ./...`, кросс-сборка четырёх бинарников и существующие нативные/ALT CI-проверки.
