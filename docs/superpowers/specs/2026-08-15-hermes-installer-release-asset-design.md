## Цель

Добавить проверенный `Hermes-Setup.exe` в существующий закрытый GitLab Release
`v0.1.0-rc.1` рядом с `certs.zip` и уточнить русскую пользовательскую инструкцию.
Официальный сайт Hermes остаётся основным способом установки, а файл из релиза —
резервным вариантом при недоступности сайта, VPN или внешней сети.

Credential Manager, хранится только в памяти процесса и не передаётся в URL,
аргументах команды или выводе.

## GitLab asset

Project Upload регистрируется в `v0.1.0-rc.1` как единственный release asset с
именем `Hermes-Setup.exe` и типом `other`. Существующий `certs.zip` не заменяется.
После добавления GitLab Release API должен вернуть оба имени. Прямая release-ссылка
проверяется как redirect на project upload; в закрытом GitLab браузерное скачивание
требует активного входа пользователя и не принимает `PRIVATE-TOKEN`. Поэтому байты
установщика скачиваются во временный файл через аутентифицированный Project Upload
API, после чего повторно проверяются размер и SHA-256. При несовпадении операция
считается неуспешной, а README не публикуется.

В разделе «Hermes в Windows» порядок установки такой:

1. Сначала попробовать официальный сайт
   `https://hermes-agent.nousresearch.com/`.
2. Если сайт или загрузка недоступны, скачать `Hermes-Setup.exe` из того же
   GitLab Release, что и Team Kit.
3. Проверить указанный SHA-256 и действительную подпись `Nous Research Inc.`.
4. Завершить графическую установку Hermes и только затем запускать Team Kit.

В списке файлов релиза добавляется прямая ссылка на `Hermes-Setup.exe`, а в таблице
контрольных сумм — его закреплённый SHA-256.

## Проверки и отказоустойчивость

- До изменения GitLab проверяется отсутствие одноимённого asset либо точное
  совпадение уже существующего удалённого файла.
- Никогда не создаётся второй asset с тем же именем.
- Загружаемые сертификаты и EXE не добавляются в Git-историю.
- `git diff --check`, тесты `test/release` и полный `go test ./...` должны пройти.
- Изменение README коммитится и отправляется в `master` только после подтверждения
  удалённого asset.
- При сбое до регистрации ссылки существующий Release и `certs.zip` не меняются;
  при сбое проверки новый README не публикуется.
