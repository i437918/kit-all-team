# Дизайн дополнений README о компонентах установки

## Цель

Дополнить актуальный README v0.1.1 информацией, необходимой пользователю до
запуска установки, не меняя структуру инструкции, продуктовый код и отдельный
Confluence-документ.

## Изменения

1. После предварительного выбора skills добавить нейтральную сравнительную
   таблицу двух взаимоисключающих наборов:
   - `cc_1c_skills от Широкова` —
     <https://github.com/Nikolay-Shirokov/cc-1c-skills>;
   - `ai_rules_1c от Филиппова` —
     <https://github.com/comol/ai_rules_1c>.
2. Сравнить назначение, основной состав, подходящий сценарий и результат
   установки. Не объявлять один набор универсально лучшим.
3. Оформить имя модели как **`generic-development`** и пояснить, что ключ
   CustomLLM используется для доступа к модели, отличается от GitLab token и
   получается по корпоративной инструкции «Подключение к LLM через API
   (IDE, SDK)».
4. Расширить пояснение `certs.zip`: архив содержит локальную цепочку доверия для
   TLS-доступа, используется при недостаточности системных сертификатов, не
   устанавливается в системное хранилище и должен загружаться только из текущего
   Release.
5. Расширить пояснение Hermes: runtime размещает профиль, bundled/Learned skills,
   провайдер CustomLLM и MCP; поддерживается `>= 0.20.1 и < 0.21.0`, Windows
   требует завершённой ручной GUI-установки, после которой Team Kit обнаруживает
   путь автоматически.
6. Добавить короткий раздел про MCP `v8std`: это read-only справочник стандартов
   и диагностик 1С для AI-помощника, endpoint `https://ai.v8std.ru/mcp`,
   документация <https://v8std.ru/mcp/>, исходный репозиторий
   <https://github.com/zeegin/v8std>. Отдельно предупредить, что в публичный
   сервис нельзя отправлять закрытый код и коммерческие данные.

## Размещение

- таблица и пояснения CustomLLM/certs/Hermes — раздел «Что подготовить до
  установки»;
- MCP — отдельный подраздел после описания устанавливаемых skills Hermes;
- остальные разделы README сохраняют текущий порядок.

## Проверка

Контрактный тест должен подтвердить наличие трёх канонических репозиториев,
официальной страницы MCP, endpoint, выделенного имени модели и расширенных
пояснений. После правок выполняются release-тесты, полный `go test ./...`,
`go vet ./...` и `git diff --check`.
