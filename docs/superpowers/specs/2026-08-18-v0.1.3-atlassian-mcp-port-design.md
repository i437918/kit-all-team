# Проект переноса корпоративных Atlassian MCP в v0.1.3

## Цель

Выпустить TeamKit `v0.1.3` как прямого наследника опубликованного тега
`v0.1.2` (`03b823588dd27e3bd0c0236f417eabbc2aef6ac4`) с обязательными Jira и
Confluence MCP для Hermes. Сохранить всё поведение `v0.1.2` и перенести только
необходимые Atlassian-возможности и два подтверждённых live-smoke исправления.

## Причина отдельного переноса

Ветка `codex/hermes-atlassian-mcp` основана на более ранней линии и не является
потомком `v0.1.2`. Прямой merge или переименование её RC2-артефакта может
удалить новые механизмы окружений, реестра, восстановления и проверки Hermes,
уже вошедшие в `v0.1.2`. Поэтому новая реализация начинается от тега `v0.1.2`,
а старые коммиты используются только как проверенная поведенческая ссылка.

## Пользовательский контракт

- Для Hermes всегда настраиваются Jira и Confluence MCP без дополнительных
  вопросов пользователю.
- Базовая авторизация обоих MCP использует обязательный
  `HERMES_CUSTOM_LLM_API_KEY` в заголовке `x-litellm-api-key` со
  значением `Bearer ${HERMES_CUSTOM_LLM_API_KEY}`.
- Jira использует только персональный `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` в заголовке
  `x-mcp-jira-authorization` со значением `Token ${HERMES_CUSTOM_ISSUE_TRACKER_TOKEN}`.
- Confluence использует только персональный `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` в заголовке
  `x-mcp-confluence-authorization` со значением `Token ${HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN}`.
- URL серверов:
  `https://llm.example.invalid/jira/mcp` и
  `https://llm.example.invalid/confluence/mcp`.
- Все три переменные обязательны, получаются и сохраняются через существующий
  защищённый механизм пользовательских секретов TeamKit.
- Токены не попадают в аргументы процессов, Git, конфигурационные квитанции,
  планы, логи и сообщения об ошибках.

## Архитектура переноса

Новая ветка создаётся от `v0.1.2`. Из старой ветки не выполняется массовый
cherry-pick. Поведение переносится небольшими изменениями в актуальных границах
`catalog/domain`, `credentials`, `hermes`, `service/reconcile` и security tests.

Конфигурация Hermes содержит только ссылки на переменные окружения. Значения
секретов сохраняются в профильном `.env` с закрытым наследованием DACL на
Windows и эквивалентными приватными правами на Unix. Существующие механизмы
обнаружения, миграции, восстановления и проверки runtime из `v0.1.2` остаются
источником истины.

Два live-smoke исправления адаптируются отдельно:

1. Корневые служебные файлы репозитория toolchain, например `.gitignore`, не
   считаются навыками и не нарушают сравнение materialized manifest. Вложенные
   файлы навыков по-прежнему хешируются, ссылки отклоняются.
2. `Hermes doctor` с кодом выхода `0` принимается только при одном из известных
   итогов: чистый успех или структурированная сводка предупреждений. Неизвестный
   либо противоречивый формат отклоняется.

## Ошибки и восстановление

Отсутствующий или пустой персональный токен останавливает план до изменения
профиля и сообщает только имя переменной. Частично завершённая операция остаётся
возобновляемой штатной командой `retry`. Существующие секреты не заменяются
пустыми значениями. Ошибка ACL не должна раскрывать содержимое файла.

## Проверка

Работа ведётся test-first. Минимальный набор доказательств:

- табличные тесты каталога и рендера двух MCP;
- тесты обязательности и защищённого сохранения трёх секретов;
- контрольные строки всех секретов во всех доступных выходах;
- регрессии для корневого `.gitignore` toolchain и двух известных итогов
  `Hermes doctor`;
- `go test ./...`, `go vet ./...` и сборка обоих исполняемых файлов;
- CI на Windows, Linux, macOS и ALT userspace;
- live smoke одноразового Hermes-профиля с реальными персональными токенами без
  вывода их значений;
- итоговые `status: ready`, пустой план и наличие точных URL и имён заголовков.

## Выпуск

Версия сборки, CI, документация и имя артефакта синхронно меняются на `v0.1.3`.
Windows-артефакт называется `teamkit-v0.1.3-windows-amd64.exe`. Релиз не
объявляется готовым до зелёного CI, проверки встроенных version/commit и
успешного live smoke. Текущий файл `v0.1.2` не перезаписывается.

## Вне области работ

- Изменение протокола корпоративных MCP или состава их инструментов.
- Добавление выбора «устанавливать MCP или нет».
- Перенос несвязанных документов и старой RC2 release-конфигурации.
- Автоматическое перевыпускание персональных токенов пользователя.
