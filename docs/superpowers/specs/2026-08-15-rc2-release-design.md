# Проект выпуска v0.1.0-rc.2

## Цель

Выпустить новый внутренний неподписанный кандидат `v0.1.0-rc.2` из текущего
кода, не изменяя тег, бинарники и историю `v0.1.0-rc.1`.

## Принципы

- Версия меняется только в активных сборочных и проверочных контрактах;
  исторические планы `rc.1` сохраняются без переписывания.
- Бинарники собираются один раз CI из отдельного release commit. В релиз
  продвигаются точные байты CI, без локальной пересборки и переименования.
- Тег создаётся только после успешного CI и указывает на тот же commit, который
  встроен в `--version` каждого бинарника.
- Четыре бинарника, `SHA256SUMS`, `SECURITY-AUDIT.json`, `certs.zip` и
  `Hermes-Setup.exe` размещаются как постоянные GitLab Release assets.
- Каждый опубликованный файл повторно скачивается через GitLab API и сверяется
  по размеру и SHA-256. Для установщика также повторно проверяется Authenticode.
- README и INSTALL получают окончательные ссылки и хеши отдельным docs-only
  коммитом после публикации, чтобы не создавать циклическую зависимость между
  release commit и заранее неизвестными хешами.

## Проверки платформ

Обязательный быстрый gate: полный Go test/vet, security audit, точная сборка
четырёх целей, запуск Windows-кандидата, запуск Linux-кандидата в Linux/ALT
userspace. GitHub native macOS/Windows/Linux и ALT QEMU запускаются, если
доступны. Отсутствующие внешние подтверждения не маскируются: они перечисляются
в release notes и `docs/EXTERNAL-BLOCKERS.md`.

## Безопасность публикации

До внешней мутации проверяется отсутствие тега и Release `rc.2`. Токены живут
только в памяти процесса и не попадают в URL, argv, лог или Git. Публикация идёт
обычным fast-forward; force-push и замена существующих assets запрещены.
