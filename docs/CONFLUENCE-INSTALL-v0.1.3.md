## Назначение

**1C Team Kit** подготавливает воспроизводимое рабочее окружение для разработки и сопровождения 1С. Пользователь отвечает на вопросы мастера, после чего программа:

- получает утверждённые файлы окружения проекта;
- загружает локальную копию конфигурации 1С;
- подключает один выбранный набор 1С skills;
- настраивает профиль Hermes либо готовит handoff для другого AI-приложения;
- настраивает провайдер CustomLLM и обязательные MCP `v8std`, `customllm-jira`, `customllm-confluence` для Hermes;
- сохраняет состояние для последующих `status`, `retry` и `update`.

**Team Kit** не изменяет системное хранилище сертификатов, не публикует секреты, не выполняет `git push` и не записывает изменения непосредственно в ветку `develop`.

> **Важно: развитие проектной ветки**
>
> После первичной установки команда проекта адаптирует документацию и настройки окружения под требования проекта и принятые практики, а затем самостоятельно публикует проверенный комплект обратно в проектную ветку, например [`content-apa`](https://gitlab.example.invalid/1c/aisuz/ai/-/tree/content-apa?ref_type=heads). **Team Kit** не выполняет `git push`: публикацию контролирует команда проекта. Благодаря этому следующие установки и обновления смогут получать из проектной ветки уже актуальный согласованный набор документации и настроек конкретного проекта.

## Что будет получено в результате

После успешной установки пользователь получает:

- отдельный каталог `KIT_ALL_TEAM_HOME` для одного проекта;
- файлы ветки `content-<project>`;
- каталог `db/` с локальной копией ветки `develop`;
- служебный каталог `.teamkit/` с планом и квитанцией операции;
- профиль Hermes вида `1c-<project>-<role>-<toolchain>` либо `.teamkit/handoff.txt` для другого AI-приложения;
- встроенные и Learned skills Hermes плюс один выбранный внешний набор 1С skills;
- три включённых MCP-сервера `v8std`, `customllm-jira`, `customllm-confluence` в профиле Hermes;
- возможность безопасно продолжить незавершённую операцию командой `retry`.

## Чек-лист перед установкой

Отметьте каждый пункт до запуска мастера:

- [ ] Есть доступ к корпоративной сети или VPN.
- [ ] Открывается `gitlab.tools.enterprise.ru`.
- [ ] Системный Git установлен и доступен из PowerShell.
- [ ] Получен логин **GitLab**.
- [ ] Получен персональный **GitLab token** с правом чтения нужных репозиториев. Инструкция: [«Получение персонального токена в GitLab»](https://docs.example.invalid/spaces/DAT/pages/323493884/Получение+персонального+токен+в+GitLab).
- [ ] Известен идентификатор проекта.
- [ ] Известна роль пользователя: аналитик, программист или архитектор.
- [ ] Выбран один набор 1С skills:
  - `cc_1c_skills от Широкова`; [Nikolay-Shirokov/cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills)
  - `ai_rules_1c от Филиппова`; [comol/ai_rules_1c](https://github.com/comol/ai_rules_1c)
- [ ] Подготовлен отдельный путь окружения, например `C:\TeamKit\apa`.
- [ ] Папка установщика `C:\TeamKitInstaller` не используется как `KIT_ALL_TEAM_HOME`.
- [ ] Выбрано AI-приложение.
- [ ] Для приложения не Hermes оно установлено и доступно через `PATH`.

Если выбран Hermes:

- [ ] Получен ключ **CustomLLM** для модели **`generic-development`**. Это отдельный ключ LLM-провайдера, а не **GitLab token**. Порядок получения ключа приведён в корпоративной инструкции [«Подключение к LLM через API (IDE, SDK)»](https://docs.example.invalid/spaces/IDP/pages/1017637995/%D0%9F%D0%BE%D0%B4%D0%BA%D0%BB%D1%8E%D1%87%D0%B5%D0%BD%D0%B8%D0%B5+%D0%BA+LLM+%D1%87%D0%B5%D1%80%D0%B5%D0%B7+API+IDE+SDK).
- [ ] Получен обязательный персональный `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` для доступа текущего пользователя к Jira.
- [ ] Получен обязательный персональный `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` для доступа текущего пользователя к Confluence.
- [ ] Для получения обоих токенов использована корпоративная [инструкция подключения mcp-atlassian](https://docs.example.invalid/spaces/BLOKL/pages/1005956195/Инструкция+по+подключению+MCP-сервера+mcp-atlassian+в+AI-ассистент+Cline); общий или чужой токен не используется.
- [ ] Скачан файл `certs.zip` из раздела `Assets` → `Other` текущего **GitLab Release**, если **Windows**, **Git** или **Hermes** не доверяют корпоративной цепочке сертификатов. **Team Kit** использует архив локально для HTTPS-подключений, но не изменяет системное хранилище сертификатов.
- [ ] Установлен **Hermes** версии `>= 0.20.1 и < 0.21.0` либо подготовлен файл `Hermes-Setup.exe` для ручной установки в **Windows**. **Hermes** создаёт изолированный профиль AI-агента, сохраняет встроенные и Learned skills, подключает выбранный внешний набор, провайдера **CustomLLM** и MCP. Совместимую установку **Team Kit** обнаруживает автоматически.

### Сравнение доступных наборов

| Набор | Основной акцент | Что содержит |
|---|---|---|
| `cc_1c_skills от Широкова` | Практическая разработка и проверка решений 1С | `72` каталога skills (`303` файла): метаданные и XML, работа с Конфигуратором, формы, отчёты, расширения и веб-клиент |
| `ai_rules_1c от Филиппова` | Общие правила и согласованные процессы работы AI-агентов с 1С | `11` каталогов skills (`115` файлов), публикуемых **Team Kit** из `content/skills`; в исходном репозитории также находятся `34` rules, `13` описаний субагентов и `13` команд |

Наборы решают разные задачи. **Team Kit** устанавливает ровно один вариант и привязывает его к проверенной версии из каталога продукта.

## Подробная установка в Windows

### 1. Создайте каталоги

Откройте Windows PowerShell и выполните:

```powershell
New-Item -ItemType Directory -Path 'C:\TeamKitInstaller' -Force | Out-Null
New-Item -ItemType Directory -Path 'C:\TeamKit' -Force | Out-Null
```

`C:\TeamKitInstaller` предназначен только для бинарника, `SHA256SUMS`, `certs.zip` и установщика Hermes. Не выбирайте его как рабочее окружение.

### 2. Скачайте Team Kit

Скачайте из [GitLab Release v0.1.3](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3):

- [teamkit-v0.1.3-windows-amd64.exe](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3);
- [SHA256SUMS](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3);
- `certs.zip` из `Assets` → `Other`, если выбран Hermes;
- `Hermes-Setup.exe` из `Assets` → `Other`, только если Hermes ещё не установлен и официальный сайт недоступен.

Сохраните файлы в `C:\TeamKitInstaller` без переименования.

### 3. Проверьте SHA-256 и версию

```powershell
Set-Location -LiteralPath 'C:\TeamKitInstaller'
$file = 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe'
if (-not (Test-Path -LiteralPath $file -PathType Leaf)) { throw "Файл не найден: $file" }
$sum = Get-Content -LiteralPath 'C:\TeamKitInstaller\SHA256SUMS' | Where-Object { $_ -match '^([0-9a-f]{64})  teamkit-v0\.1\.3-windows-amd64\.exe$' } | Select-Object -First 1
if ($sum -notmatch '^([0-9a-f]{64})  ') { throw 'Не найдена строка SHA-256 для Windows-бинарника' }
$expected = $Matches[1]
$actual = (Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA-256 не совпадает: ожидался $expected, получен $actual" }
Write-Host "SHA-256 совпадает: $actual"
& $file --version
```

Ожидаемая версия:

```text
"version":"v0.1.3"
```

При несовпадении остановитесь и скачайте файл заново. Не отключайте антивирус или системную защиту целиком.

### 4. Подготовьте Hermes или другое AI-приложение

#### Вариант 4A. Hermes уже установлен

Ничего дополнительно устанавливать не нужно. Team Kit автоматически проверит:

- безопасные стандартные каталоги Hermes;
- первый `hermes` в `PATH`;
- версию `>= 0.20.1 и < 0.21.0`;
- совместимую schema конфигурации 34 или 37;
- доступный bundled skills catalog.

Не вводите `HERMES_HOME`. Обычный интерактивный мастер его не запрашивает.

#### Вариант 4B. Hermes ещё не установлен

1. Скачайте Hermes с [официального сайта](https://hermes-agent.nousresearch.com/).
2. Если официальный сайт недоступен, используйте `Hermes-Setup.exe` из Release.
3. Для резервного файла проверьте актуальную подпись издателя по организационной процедуре; не переносите контрольные суммы или thumbprint из прежнего выпуска.
4. Запустите установщик двойным щелчком.
5. Завершите графический мастер.
6. Закройте PowerShell и откройте новое окно.
7. Вернитесь к шагу 5 этой инструкции.

#### Вариант 4C. Другое AI-приложение

Установите выбранное приложение до Team Kit. Поддерживаются Hermes, Cursor, Claude Code, Codex, OpenCode, Kilo Code, Kimi, Qwen, Command Code, Cline и Pi.

После установки откройте новое окно PowerShell. Если приложение не найдено через `PATH`, Team Kit завершится с `AI_APP_REQUIRED` до создания окружения.

### 5. Запустите мастер

```powershell
& 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe' apply
```

Первый экран:

```text
Что вы хотите сделать:
  1. Добавить новое окружение
  2. Обновить существующее окружение
Введите номер ответа:
```

Если первым вопросом стала операционная система, остановитесь и повторно проверьте `--version`: запущен не текущий файл.

### 6A. Добавьте новое окружение

Выберите `1`.

#### Последовательность вопросов

| Вопрос | Ответ |
|---|---|
| Операционная система | `1 — Windows` |
| AI-приложение | Номер выбранного приложения |
| Установлено ли AI-приложение | Только для приложения не Hermes: `1 — Да` |
| `KIT_ALL_TEAM_HOME` | Новый абсолютный путь, например `C:\TeamKit\apa` |
| Проект | Номер проекта |
| Роль | `1 — Аналитик`, `2 — Программист`, `3 — Архитектор` |
| Набор skills | `1 — cc_1c_skills от Широкова` или `2 — ai_rules_1c от Филиппова` |

Проекты мастера:

| № | Проект | № | Проект |
|---:|---|---:|---|
| 1 | `aisuz` | 7 | `esed` |
| 2 | `apa` | 8 | `uat` |
| 3 | `asbnu` | 9 | `unip` |
| 4 | `asku` | 10 | `zup` |
| 5 | `easr` | 11 | `wms` |
| 6 | `eisko` | | |

Для Hermes мастер **не** спрашивает:

- установлено ли приложение;
- `HERMES_HOME`;
- версию Hermes.

Если эти вопросы появились, остановитесь и проверьте текущую версию EXE.

#### Запрос секретов

Когда сеть действительно понадобится, значения вводятся маскированно, без отображения символов:

- логин GitLab;
- GitLab token;
- `HERMES_CUSTOM_LLM_API_KEY` — ключ CustomLLM, только для Hermes;
- `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` — Jira personal token, только для Hermes;
- `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` — Confluence personal token, только для Hermes.

Не вставляйте секреты в командную строку, URL Git, Confluence, тикеты или сообщения.

### 6B. Обновите существующее окружение

Выберите `2`.

Team Kit определяет окружение в порядке:

1. `--kit-home`, если параметр передан;
2. локальный MRU-реестр;
3. переменная `KIT_ALL_TEAM_HOME`;
4. ручной ввод пути.

Если окружение одно, оно выбирается автоматически. Если несколько — выберите номер. Последний пункт `Указать другой путь` позволяет ввести абсолютный путь вручную.

После сводки выберите область обновления:

| № | Действие |
|---:|---|
| 1 | Ничего. Команда завершится без сети и записи. |
| 2 | Только файлы окружения. |
| 3 | Только файлы базы данных. |
| 4 | Файлы окружения и базы данных. |

Если Team Kit сообщает `RETRY_REQUIRED`, не запускайте новое обновление. Используйте шаг 6C.

### 6C. Продолжите незавершённую операцию

1. Прочитайте стабильный код ошибки.
2. Устраните причину.
3. Не удаляйте `.teamkit/`, `.env`, профиль Hermes или уже загруженные файлы.
4. Выполните всю напечатанную Team Kit команду `retry` либо:

```powershell
& 'C:\TeamKitInstaller\teamkit-v0.1.3-windows-amd64.exe' retry --kit-home 'C:\TeamKit\apa'
```

Во время `retry` программа повторно проверяет окружение и продолжает только незавершённые действия.

Для доказанного staging `.env`, созданного этой операцией, v0.1.3 устанавливает owner-only права без изменения байтов. Для точного TeamKit-owned профиля с прежним marker выполняется один официальный `hermes -p <identity> skills opt-in --sync`. Пользовательский opt-out не изменяется.

## Как устроен профиль Hermes

Team Kit v0.1.3 создаёт профиль без `--no-skills`. Это означает:

- встроенные skills Hermes сохраняются;
- Learned skills сохраняются;
- пользовательские skills не удаляются;
- добавляется только один выбранный внешний набор Team Kit;
- конфликт имён с bundled skill останавливает установку до изменения профиля;
- после сбоя публикация выбранного набора продолжается через `retry`;
- в `config.yaml` добавляются CustomLLM и MCP `v8std`.

### Always-on Jira и Confluence

Для профиля Hermes Team Kit автоматически включает MCP Jira и Confluence. `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` и `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` обязательны и должны быть персональными токенами текущего пользователя. Маскированные запросы содержат `HERMES_CUSTOM_LLM_API_KEY`, `HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` (`Jira personal token`) и `HERMES_CUSTOM_KNOWLEDGE_BASE_TOKEN` (`Confluence personal token`). Значения сохраняются только в protected owner-only profile `.env`; не передавайте их через аргументы или URL. При устранимой ошибке используйте `retry`, который продолжает незавершённую операцию без нового `apply`.

Пример имени профиля:

```text
1c-apa-developer-cc_1c_skills
```

## MCP v8std

Для профиля **Hermes** программа добавляет MCP-сервер `v8std`. Он предоставляет AI-агенту доступ к базе стандартов и диагностик 1С: позволяет искать стандарт по номеру или фразе, получать полный текст требования, находить связанные рекомендации и пояснять диагностики BSL, EDT и АПК. MCP не изменяет код проекта и не запускает проверки самостоятельно.

- описание сервера и доступных инструментов: [v8std MCP](https://v8std.ru/mcp/);
- исходный код: [zeegin/v8std](https://github.com/zeegin/v8std).

Это внешний публичный сервис: текст поискового запроса передаётся серверу. Не отправляйте закрытый код, коммерческие данные, токены, пароли и другие секреты. Для поиска используйте обезличенный вопрос, номер стандарта или текст диагностики.

## MCP Jira

Сервер `customllm-jira` всегда включён для профиля Hermes. Он предоставляет AI-агенту работу с доступными текущему пользователю проектами и задачами Jira: поиск и чтение задач, полей и комментариев, а также поддерживаемые сервером операции в пределах персональных прав.

- URL: `https://llm.example.invalid/jira/mcp`;
- базовая авторизация: `x-litellm-api-key: Bearer ${HERMES_CUSTOM_LLM_API_KEY}`;
- персональная авторизация: `x-mcp-jira-authorization: Token ${HERMES_CUSTOM_ISSUE_TRACKER_TOKEN}`.

`HERMES_CUSTOM_ISSUE_TRACKER_TOKEN` обязателен. Team Kit хранит его только в owner-only `.env` профиля; `config.yaml` содержит `${HERMES_CUSTOM_ISSUE_TRACKER_TOKEN}`, но не значение токена.

## MCP Confluence

## Диагностика и восстановление

| Код | Причина | Действие пользователя |
|---|---|---|
| `AI_APP_REQUIRED` | Приложение не установлено или отсутствует в `PATH`. | Установить, открыть новый PowerShell, повторить `apply`. |
| `HERMES_HOME_AUTO_DETECT_FAILED` | Hermes не найден безопасно и однозначно. | Завершить GUI-установку, открыть новый PowerShell, повторить. |
| `HERMES_VERSION_UNSUPPORTED` | Версия вне `>= 0.20.1 и < 0.21.0`. | Установить поддерживаемую версию. |
| `HERMES_EXECUTABLE_UNVERIFIED` | Исполняемый файл или его возможности не подтверждены. | Проверить первый `hermes` в `PATH`; не обходить проверку случайным путём. |
| `HERMES_CONFIG_SCHEMA_UNSUPPORTED` | Schema runtime не равна доказанной 34 или 37. | Установить поддерживаемый Hermes; не править конфиг вручную. |
| `HERMES_BUNDLED_SKILLS_USER_OPT_OUT` | Marker был изменён пользователем. | Остановиться и решить с владельцем профиля, нужен ли opt-in. |
| `CERTIFICATE_ARCHIVE_REQUIRED` | Отсутствует проверенный `certs.zip`. | Скачать из текущего Release и положить рядом с бинарником. |
| `SECRET_FILE_PERMISSIONS_UNSAFE` | Приватный файл не owner-only. | Выполнить `retry`; при повторе передать администратору exact path без содержимого. |
| `RETRY_REQUIRED` | Есть незавершённая квитанция. | Выполнить напечатанную команду `retry`. |
| `LOCAL_CHANGES_DETECTED` | В рабочем Git-дереве есть изменения. | Самостоятельно сохранить изменения и повторить. |
| `FOREIGN_WORKSPACE` | Выбрана чужая или непустая папка. | Выбрать отдельный пустой каталог либо правильное окружение. |

### Что нельзя делать после ошибки

- не удалять `.teamkit/`;
- не удалять `.env`;
- не расширять права приватного файла для групп пользователей;
- не создавать `config.yaml` или MCP вручную;
- не копировать вручную каталоги skills в профиль;
- не выполнять повторный `apply` в том же незавершённом окружении;
- не передавать токены в запрос поддержки.

### Что приложить к обращению в поддержку

- версия Team Kit из `--version`;
- стабильный код ошибки;
- путь `KIT_ALL_TEAM_HOME`;
- выбранные проект, роль, AI-приложение и toolchain;
- результат `status --kit-home`;
- указание, новый это профиль или обновление;
- наличие VPN и доступа к GitLab.

Не прикладывайте значения токенов, ключей, содержимое `.env`, `certs.zip` или приватные конфиги.

## macOS

Поддерживаются **macOS 15** на Intel и Apple Silicon. До начала подготовьте VPN, доступ к **GitLab**, системный **Git**, ключ **CustomLLM** для **Hermes** и отдельный каталог окружения, например `$HOME/TeamKit/apa`.

### Шаг 1. Определите архитектуру

```bash
uname -m
```

- `x86_64` — используйте `teamkit-v0.1.3-darwin-amd64`;
- `arm64` — используйте `teamkit-v0.1.3-darwin-arm64`;
- при другом результате остановитесь: подходящего бинарника в выпуске нет.

### Шаг 2. Скачайте и проверьте файлы

1. Создайте каталог `$HOME/TeamKitInstaller`.
2. Из **GitLab Release v0.1.3** скачайте [бинарник Intel](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3) либо [бинарник Apple Silicon](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3), а также [SHA256SUMS](https://gitlab.example.invalid/1c/aisuz/ai/-/releases/v0.1.3).
3. Выполните:

```bash
cd "$HOME/TeamKitInstaller"
binary='teamkit-v0.1.3-darwin-arm64' # для Intel укажите teamkit-v0.1.3-darwin-amd64
expected="$(awk -v file="$binary" '$2 == file {print $1}' SHA256SUMS)"
actual="$(shasum -a 256 "$binary" | awk '{print $1}')"
test -n "$expected" && test "$actual" = "$expected" || { echo 'SHA-256 не совпадает'; exit 1; }
chmod 700 "$binary"
"./$binary" --version
```

Версия должна быть `v0.1.3`. Бинарники не подписаны Apple и не notarized; разрешайте запуск только способом, одобренным организацией.

### Шаг 3. Запустите мастер

```bash
"./$binary" apply
```

В первом меню выберите `Добавить новое окружение` либо `Обновить существующее окружение`. При добавлении выберите `macOS`, AI-приложение, проект, роль и один набор skills. **Hermes** устанавливается и проверяется **Team Kit** автоматически; `HERMES_HOME` вручную вводить не нужно.

### Шаг 4. Проверьте результат

```bash
"./$binary" status --kit-home "$HOME/TeamKit/apa"
```

Ожидаемый статус — `ready`. Для **Hermes** проверьте встроенные skills, выбранный внешний набор и MCP `v8std`. После устранимой ошибки используйте напечатанную команду `retry`, не удаляя `.env` и `.teamkit/`.

## Ограничения и правила безопасности

- Team Kit v0.1.3 — внутренний неподписанный выпуск.
- Сборки macOS не подписаны Apple и не notarized.
- Установка Hermes в Windows выполняется вручную через GUI.
- ALT Linux подтверждена только в p11 userspace.
- Trusted corporate network probe не входит в release-gate.
- Офисные документы не поддерживаются.
- Один `KIT_ALL_TEAM_HOME` используется только для одного проекта.
- `HERMES_HOME` и `KIT_ALL_TEAM_HOME` не должны быть вложены друг в друга.
- Секреты нельзя передавать через командную строку, URL, Confluence или сообщения.
- `.env`, `.teamkit/`, `db/`, `certs.zip` и каталоги профилей нельзя публиковать.
- Между `apply` и `retry` следует использовать одну и ту же учётную запись Windows.
